# Experimental Setup

## 1. Hardware and Software Environment
The benchmark was conducted on a controlled hardware and software environment to ensure deterministic and reproducible execution. The experiments were run on macOS 23.0.0 (Apple Silicon ARM64 architecture). The environment utilized Python 3.13.7. 
The mathematical solvers used included:
- PySAT (python-sat) with the Glucose3 solver
- OR-Tools CP-SAT (version 9.15.6755)
- Gurobi Optimizer (version 13.0.3)
- IBM ILOG DOcplex (version 2.32.264) and CPLEX (version 22.2.0.0)
- IBM CP Optimizer (called via docplex.cp)

## 2. Benchmark Protocol
The study rigorously evaluated 9 distinct solving methods (5 Boolean SAT encodings, 2 Constraint Programming methods, and 2 Mixed Integer Programming methods) across 11 instance sizes for the N-Queens problem ($N \in \{4, 8, 16, 20, 31, 32, 40, 44, 50, 64, 100\}$). To ensure statistical reliability and capture execution variance, each method-size configuration was repeated 5 times, yielding a total of 495 planned official trials.

To guarantee fairness and prevent resource contention or state sharing, every single trial was executed in an isolated subprocess. All methods were strictly configured to use single-threaded execution (`workers=1`, `threads=1`) with a deterministic global random seed (`random_seed=0`). A strict internal time limit of 300.0 seconds was enforced at the solver level, supplemented by a 330.0-second external subprocess termination mechanism to handle unresponsive processes. For all Boolean SAT encodings, the Glucose3 phase selection policy was fixed to `solver_default` to ensure uniform heuristic behavior, thereby eliminating algorithm-specific search tuning as a confounding variable.

## 3. Evaluated Metrics
The primary metric for performance evaluation is **pipeline total time**, which comprehensively captures the end-to-end framework execution time, including model construction, solver instantiation, constraint propagation, search, and final independent validation.

Secondary and diagnostic metrics recorded include:
- **Process wall time**: The total wall-clock time of the isolated subprocess.
- **Structural counts**: The exact number of primary variables, auxiliary variables, and Conjunctive Normal Form (CNF) clauses generated by SAT encodings.
- **Completion reliability**: The success rate (number of valid solutions found within the time limit) and the number of timeouts (TIMEOUT). 
- **License restrictions**: Runs blocked by proactive license constraints (BLOCKED_LICENSE) were explicitly recorded to differentiate solver capacity limitations from algorithmic failures.

## 4. Correctness Checking
To ensure construct validity, every resulting output was subjected to an independent algorithmic validator. Regardless of the solver's native reported status (e.g., `OPTIMAL`, `FEASIBLE`, `SAT`), the final positions of the queens were decoded and mathematically verified to satisfy all row, column, main diagonal, and anti-diagonal constraints. Only configurations passing this strict validation were recorded as successful (`SAT` and `Valid=True`) trials.
